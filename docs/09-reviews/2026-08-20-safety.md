# Safety review — 2026-08-20

- Reviewer: internal Codex sub-agent
- Reviewed commit: `c38873026222175433fb86f2fcac1a655ffcc932`
- Method: read-only schema abuse cases and normative-document comparison
- Verdict: **Request changes**

No P0 issue was found. The review reproduced six unsafe P1 combinations that
the reviewed schemas accepted.

## P1 findings

### User provenance is sender-asserted

An adapter could label its own envelope `actorType: user`. Effective provenance
must separate claimed author from an authenticated control-plane principal.
Only a trusted control plane may assert user authorship or bind a user approval
attestation.

The experimental coordinator rejected user provenance from a task principal.
The later JSON-RPC binding also removes principal fields from request params and
compares claimed authorship with a transport-derived principal.

### Grants can appear self-issued

The reviewed grant schema accepted an agent as `grantedBy`. Grant proposals and
effective control-plane-issued grants must be separate. Effective grants need
an authenticated issuer, owner or policy decision reference, and versioned
update rules.

The experimental coordinator installs grants only through user or policy
authority and rejects agent issuers.

### Revocation did not cover queued suggestions

Any message that has not entered context or been submitted to an adapter must
be reauthorized against the current grant, including `notify` and `suggest`.
Otherwise a revoked peer can leave delayed prompt-injection content in a
mailbox. The experimental coordinator performs this check at response and
context admission.

### External verification was only an arbitrary reference

`externally-verified` needs a typed attestation containing verifier identity,
claim subject, method, evidence digest, time, and trust-policy decision. A plain
URI must not upgrade an adapter claim into independent verification.

### Partial interruption was not representable

Model-turn, tool-call, and subprocess cancellation can have different results.
ThreadMesh needs a typed per-target interruption outcome before any adapter
claims interrupt support. The experimental Kimi profile deliberately advertises
no interrupt capability.

### Restricted summaries could be public

Sensitivity, audience, and grant summary visibility need enforced projection
rules. At minimum, `restricted + public` must be invalid, and relationship
scoped reads must reauthorize against the current effective grant.

## P2 findings

- Decision states and reason codes can contradict each other.
- Relationship vocabulary and parent/child direction are inconsistent.
- Capability documents can declare unsafe intent, delivery, freshness, and
  cancellation combinations.

## Approval condition

Resolve authenticated provenance and grant issuance first, followed by
revocation-at-admission, typed interruption/verification, and summary
projection constraints. Add a negative fixture for every reproduced abuse case.

## Prototype follow-up

Pull request [#20](https://github.com/fyaic/threadmesh/pull/20) added stored task
owners, mandatory grant issuer identity, target-owner revocation, current-grant
checks before durable admission claims, canonical JSON untrusted-peer rendering,
adapter evidence binding, a child environment allowlist, and real permission
denial tests. Documentation now states that principals are trusted injection
points and ACP does not provide a native peer role or OS sandbox. The reviewer
approved the conservative experimental prototype after re-review.

The later coherence and authenticated binding changes resolve normative
authentication, grant issuance, and summary projection under #15 and #18.
Typed verification attestations and interruption semantics remain open in
[#16](https://github.com/fyaic/threadmesh/issues/16).
