# Mainline product acceptance review

Date: 2026-09-05. Baseline: `98bba82`.
Internal independent subagent review, not an external user report, adoption
result, or a new live-model test. Source and evidence inspection only.

## Verdict

The project has demonstrated useful model-selected collaboration in two Pi
sessions. It has **not yet demonstrated the complete requested experience**:
existing everyday sessions on different harnesses contact one another without
human relaying, retain their working context, and respect the receiver's work.
The next milestone must close that experience gap, not add another protocol,
visual redesign, or collection of passing unit tests.

## Prompting, identity and consent audit

- The ordinary task prompts do not prescribe a recipient, send command or
  message. However, the Pi extension adds explicit generic coordination
  instructions, peer-goal hints and inbox data. Describe this as **configured
  model-selected initiative**, never as absent prompting or guaranteed autonomy.
- Both successful fixtures tell the receiver to keep its output aligned with a
  shared source as it evolves. The receiver also volunteered a dependency
  message before the source task. This is valid collaboration, but not a blind
  source discovering an unknown dependency independently of any peer message.
- A ThreadMesh name is a persistent workstream, not a discovered native chat ID.
  `run` starts a process; native resume is a separate host behavior. `continue`
  explicitly starts a new session with a checkpoint. Neither proves attaching
  to an already-open arbitrary tab.
- Joining deliberately shares published goals and advice inside a same-owner
  room. Codex's four workspace operations are preapproved for that invocation;
  Pi idle wake is separately opted in. Explain these choices before launch.
- Pi's follow-up guard is encouraging, but it does not by itself establish that
  partially typed user input or a near-simultaneous new turn cannot be disturbed.
  Keep this narrower than a claim of universal noninterference.

## One practical next experiment

Use an already-authenticated **Codex sender and Pi receiver** in a disposable
copy of a small real project, through the public launcher. Save all native
versions, public commands, ordinary prompts and injected integration guidance.

1. In a native Pi session, establish a legitimate project constraint that is
   not repeated in the next task (for example, preserve an approved price).
   Keep that same native session running for subsequent work. Verify retained
   session identity and context; do not replace it with a seeded summary.
2. Publish workstream goals once and opt into Pi idle wake. Give the receiver
   normal page-maintenance work; later ask Codex to update the approved brief.
   Do not name the recipient or ask either model to use messaging tools.
3. Require Codex to choose a relevant message and Pi to resume without a second
   user prompt, produce the correct file change, and retain the earlier private
   constraint. A receipt or checkpoint alone is not the business result.
4. Inspect the event ordering and changed files. Record unrelated inbox count,
   failed attempts and all human interventions. Keep a failed run as a failure;
   do not repair it with a manual send and call it autonomous success.
5. Separately test message arrival while Pi is busy, with a queued user task.
   Assert the peer message does not steer the running task or overtake the user.
   Deterministic host-lifecycle tests are useful here but must stay labelled as
   such until a native busy-receiver run verifies the host behavior.

## Completion rule and scope control

Accept this increment when cross-harness model-selected contact reaches the
same already-started native receiver, produces a useful artifact and retains
its earlier constraint. This still does not prove adding ThreadMesh to an
arbitrary previously unconnected tab: native resume/attachment is a subsequent
explicit adoption gate. If only a fresh-session case passes, publish that
narrower result. Passing a tool authorization diagnostic alone is insufficient.

Quota continuation and DeepSeek model verification remain separate open gates;
missing provider credentials cannot be replaced with a transport test. Do not
claim a star target or independent adoption from maintainer/subagent activity.
After one reproducible product case, ask one real user to follow the public
guide and report the first failed step without maintainer-only repairs.

Code is mergeable; the [API run](artifacts/2026-09-05-codex-pi-api.json) passes
independent digest, same-receiver, actual-write, two-page and empty-page checks.
This is reciprocal collaboration, not blind-source contact or old-tab adoption.
The second copy case fails quality acceptance: delivery and same-session edit
succeeded, but Pi dropped “free” from the claim. The overall quality gate is open.
