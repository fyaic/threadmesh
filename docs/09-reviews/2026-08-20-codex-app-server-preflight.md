- Generated protocol files: `273`

  `sha256:6138e09146c1581af98382f4e2f6b185ccc6eafa0a61481bfaabced4d3edbde3`
- Sanitized initialize snapshot digest:
  `sha256:c002bc7f6c626261612c683458d14aa4e39cc98a18ce87aa274d42787bf40634`

The protocol digest hashes sorted relative file names and recursively
key-sorted canonical JSON, separated by null bytes. Canonicalization removes the
generator's nondeterministic object-key order without changing schema meaning.
The temporary schema directory is deleted after the run. The initialize
projection deliberately excludes `codexHome`.

Two consecutive real generations produced the same canonical digest. Hashing
raw generated bytes is intentionally avoided because one aggregate schema emits
semantically equivalent definition keys in nondeterministic order.

## Real product preflight

`npm run smoke:codex` passed against the installed product without starting a
model turn:

- initialize/initialized handshake passed;
- App Server reported Unix/macOS and a `0.145.0` user agent;
- `thread/start` returned an exact thread ID under `never` approval and
  `read-only` sandbox settings;
- the process exited cleanly and no durable rollout was created.

An earlier preflight attempted to resume the empty thread and received
`-32600: no rollout found for thread id`. Repeating within the same App Server
connection produced the same product behavior. The adapter and smoke report now
label empty-thread persistence as `unproven-before-first-turn`; they do not turn
this limitation into a pass.

The fixture proves adapter behavior, not Codex model behavior.

## Live marker gate

`npm run smoke:codex:live` remains intentionally not run. It now aliases the
single common live runner, which will:

1. create a fresh persistent thread and submit a bounded local bootstrap turn
   on the same connection, without labelling it as peer context;
2. require the exact untruncated `CODEX_THREADMESH_LIVE_OK` response, a terminal
   completed turn, and zero server-side approval requests;
3. resume the persisted thread from a fresh App Server process;
4. delete the exact created thread and fail if cleanup cannot be proven.

The coordinator-mediated peer suggestion follows only after registration and
receiver acceptance. The live marker remains gated by authenticated independent
M0 review (#7), a clean local `main` equal to GitHub `main`, and merger/retest of
the M1 coordinator stack.
