# 愿景

我们想抽离的不是普通“跨 session 发消息”，而是下面这种行为：

> Agent A 在执行过程中形成了对多任务环境的局部理解，发现 B 与当前目标存在因果依赖，于是主动选择通知、建议、纠偏或停止 B。

这类行为让人感到“智能”，因为消息的目标、时机、内容和理由并不是传统工作流全部预先写死的。但这种主动性只有在边界清楚时才有价值。

## ThreadMesh 的产品承诺

**让 agent 有主动协调任务的能力，但不让它们隐形地控制彼此。**

因此项目会同时建设两部分：

- 能力面：任务发现、依赖表达、主动决策、mailbox、等待、反馈和重规划；
- 治理面：关系权限、目标版本、来源标签、接收方同意、中断预算和审计。

ThreadMesh 希望让不同 harness 通过 adapter 共享这套语义，而不要求统一模型、prompt、工具系统或 agent loop。
