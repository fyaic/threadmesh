# First useful collaboration

Date: 2026-09-05. Baseline: `38178e1`.

## Outcome

An operator connects two of their own agent harnesses to an explicitly shared
local workspace. A model can discover the other's goal, send useful context,
and read a persistent inbox. A saved checkpoint can carry work to a different
harness when the original provider has no quota. Real model execution is
distinguished from a no-model onboarding preview.

## Execution order

1. Ship a persistent local workspace and four bounded model tools, with a
   public MCP entry point and invocation-scoped harness configuration.
2. Include official DeepSeek Harness (`dsh`) through its documented MCP/ACP
   surfaces, plus existing Codex, Kimi and Pi paths. Verify installed versions
   and report unavailable credentials without claiming model success.
3. Exercise real tasks with ordinary goals, multiple possible peers, useful
   artifacts, and no task-specific instruction prescribing who to contact.
4. Make checkpoints, receiver decisions, and status observable; document quota
   continuation as a transfer of explicit context, not hidden model state.
5. Fix stale public evidence and failed-onboarding feedback; publish installation
   instructions, practical recipes, and a truthful response to issue #79.
6. Publish a reproducible alpha and earn early adoption before broader outreach.

## Product constraints

Implementation checkpoint: local workspace/MCP/launchers, native DeepSeek tool
validation, a real Pi-pair file-changing loop and a real Pi checkpoint recovery
are retained in the [dated validation](../09-reviews/2026-09-05-first-use-validation.md).
Earlier Codex ordinary-task attempts did not pass; Kimi hit its weekly quota;
DeepSeek live model lacks credentials. Do not merge these evidence levels into
“all agents work automatically”. The [community launch plan](community-launch-2026-09-05.md)
defines the next adoption gates and competitor-derived acceptance checks.

Follow-up [awareness/copy validation](../09-reviews/2026-09-05-workspace-awareness.md):
approved terminology now has its own real Pi file-changing case. Codex work is
focused first on the observed native MCP approval cancellation, then native
task-start awareness, not another routing framework. The scoped approval and
actual context-hook execution passed separate checks. A subsequent unchanged
ordinary Codex → Pi API task now passes through model-selected advice and the
same native receiver's own client edit, without user relay. Pi volunteered its
dependency first; this is reciprocal collaboration, not blind discovery.
The [current acceptance plan](cross-harness-acceptance-2026-09-05.md) tracks the
second cross-harness task, fresh non-contact control and remaining adoption gaps.

- Explicitly joining one local workspace permits members to discover the goals
  published there and send advisory messages. This is a trusted-process local
  experience; it does not widen the core protocol's authority model.
- Ordinary inbox reads do not consume messages. Acceptance is separate from a
  successful business result. No silent interruption or automatic resend of an
  unknown external effect.
- No global configuration replacement, account rotation, quota bypass, or
  claim that subscription context can be transferred losslessly.
- A shared constraint is published deliberately; private histories are not
  automatically scanned or broadcast.
- Keep the M5 evidence archive, but do not make another five-role audit loop a
  prerequisite for a usable two-agent advisory experiment.

Competitor issues worth turning into acceptance checks:

- [Repowire #208](https://github.com/prassanna-ravishankar/repowire/issues/208):

- [Agent Mail #254](https://github.com/Dicklesworthstone/mcp_agent_mail/issues/254):
  reading an inbox must not silently consume it.
- [Agent Mail #263](https://github.com/Dicklesworthstone/mcp_agent_mail/issues/263):
  address ongoing work clearly instead of requiring ephemeral model IDs.

Target: 100 legitimate stars. Leading indicators: independent successful
installs, useful collaborations, repeat usage, and one external integration.
No purchased stars, unsolicited issue spam, or guaranteed growth claim.
After live evidence, prepare one concise demo post for relevant harness
communities and a useful DeepSeek ecosystem integration submission. Track
which channel produces successful users, not clone counts alone.
