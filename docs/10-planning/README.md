# Project planning

This directory is the canonical home for current project status and execution
planning. The roadmap describes milestone outcomes; these documents describe
where the repository is now and what work should happen next.

- [Project status](project-status.md) — evidence-backed snapshot of shipped,
  experimental, blocked, and unstarted work.
- [Native value acceptance](native-value-acceptance-2026-10-10.md) — small matched
  API-to-client comparison, currently paused; separate installation gates and
  an unfilled result table.
- [Product mainline](product-mainline-2026-08-28.md) — August product thesis,
  community evidence, Now/Next/Later priorities, metrics, and stop conditions.
- [M5 sprint 1](m5-sprint-1.md) — bounded parallel workstreams, dependencies,
  acceptance gates, risks, and the sequence into real-agent validation.
- [M5 real Codex loop](m5-real-codex-loop.md) — staged #91 execution plan and
  strict closure evidence for initiative, controls, persistence, and cleanup.
- [M5.2 implementation contract](m5-2-implementation-contract.md) — exact
  session, Git evidence, independent-verifier, unlock, and no-go boundaries.
- [M5.2 real Codex scenario](m5-2-real-codex-scenario.md) — concrete persistent
  role topology, model-owned tool turns, durable promotion sequence, recovery
  boundaries, and delivery slices for the live run.
- [Mainline plan](mainline-plan.md) — completed protocol/runtime workstreams and
  the historical transition from technical gates to product work.
- [Milestone acceptance audit](acceptance-audit.md) — criterion-by-criterion
  evidence and the remaining merge, real-product, and evaluation gaps.

Read the latest project-status entry first. Older plans retain their historical
priorities and do not override the current validation pause.

Status statements are dated and should be updated whenever a pull request
materially changes a milestone exit criterion. GitHub milestones and issues are
the source of truth for acceptance and closure.
